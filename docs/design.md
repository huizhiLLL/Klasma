# Klasma 设计约束

本文只记录已确认的设计点与约束，是 UI/UX 工作的默认依据。讨论经过、候选参数、参考与未决问题见 [设计过程记录](design-process.md)，仅需追溯时读取。样张和草图表达设计，不自动确认其全部数值。

## 1. 定位与工作边界

- 公开前台是个人策展、收藏和作品展示空间，采用浅色单主题，清爽、干净，同时张扬、飘逸、灵动，强调个人偏好与编排。
- 三个集合为软件（Tools）、作品（Projects）、工程资产（Library），前景表达分别为 `What I prefer`、`What I make`、`What I keep`。
- 避免或尽可能减少搜索、筛选、统一列表和高密度信息；既有 API 不决定前台必须出现哪些控件。
- 各集合采用不同布局；展示顺序允许表达个人偏好、内容关系与叙述。一致性由排版、导航、反馈和返回体验建立。
- 后台以效率与清晰为先。录入先以标题、类型、链接或文件、简短说明保存，详细内容允许后补；共用编辑器骨架，按类型补充差异字段。
- 已完成前期主题稿和布局原型评审，用户决定进入**正式前端实施阶段**。已确认的设计意图与交互约束作为实现依据；尚未确认的具体数值、响应式细节继续在真实页面中验证，不能把全部原型参数视作定稿。

## 2. 首页与收藏牌

- 首页展示头像、名称（会枝 / huizhiLLL）、简短签名、社交链接，以及 Blog / Weekly 入口。个人区域保持轻盈，三张收藏牌仍是视觉与交互主体。
- 首页采用「左侧个人身份 / 右上空间说明」的分工：左侧保留个人资料和主要链接；右上显示「个人数字碎片库」与 `What I prefer · make · keep`，不把社交链接全部搬到右侧。
- 说明 Klasma / κλάσμα 的「碎片、片段」含义，并交代实际收藏的软件、作品与工程资产；感性签名不能替代用途说明。不采用商业 Landing Page 的营销结构。右上短句负责定位，站名释义和内容说明负责解释，不重复堆叠相同文案。
- 站名释义与内容说明紧邻 Klasma 标题右侧，窄屏空间不足时就近换行；不分散到页面最右侧。正式页面不显示预览提示 / 状态切换 / 字体归属页脚，不显示「选择一张牌」引导与牌面「进入」文字；保留牌面箭头。
- 首页三张牌就是主导航，不放完整的全局胶囊导航。
- 采用现代收藏牌的竖向形态、挑选仪式与抽牌体验，不采用传统塔罗符号、插画或金边装饰。
- 三张牌整体对称、地位平等、构图平衡；个体允许错位、倾斜、高低差与适度重叠，摆放张扬灵动。
- 牌面采用较透明、低视觉权重的素材背景，前景为简洁中英文标题与辅助图形，不另加简介；保持明确边界、层次与入口辨识度。

| 牌面标题 | 素材背景方向 |
| --- | --- |
| 软件 / What I prefer | 软件 logo 墙，横向瀑布流构图 |
| 作品 / What I make | 作品相关界面截图与 logo 背景墙 |
| 工程资产 / What I keep | SFM 代码、蓝图结构、3D 图等工程素材，不永久限定为 Minecraft |

## 3. 集合页全局导航

- 三个集合页统一只保留 `What I prefer / make / keep` 主标题，不再显示标题下的中文集合名称与说明。

- 桌面集合页左上是标题，右上为稳定的横向胶囊，依次为独立 Home 图标、Prefer、Make、Keep。首页头像只负责身份，不与 Home 图标做共享元素过渡。
- 首页右上角的 `prefer / make / keep` 是说明文字，不是第二套导航。进入集合时，这三个具体词分别作为共享元素变换为胶囊中的三个词项；说明标题 `个人数字碎片库`、`What I` 前缀与分隔点退场，胶囊底板、选中状态和独立 Home 图标出现。
- 返回首页时，胶囊可以反向重组成原说明文字；若刷新、直达链接、浏览器历史或移动端布局不适合共享元素转场，直接显示正确的静态状态或采用局部淡入淡出。
- 当前集合有明确选中状态，切换时选中背景连续滑动；Home 返回首页并退出胶囊。
- 集合主标题共用 `What I`，三个词保持同一滚轮中的连续位置关系，字形左缘对齐；上下候选词与当前词按可见字形边缘保持视觉等距，考虑 p 等字母的下伸部；上下两个候选词保持清楚可辨的大小。当前词上下位移时同步放大 / 缩小，邻词接续进入，不用新旧文字独立淡入淡出代替；辅助候选词不重复进入有效标题语义。
- 胶囊选中项、标题滚轮、集合内容和 URL 对应同一个导航状态。任意集合可直接访问或切换，不要求播放中间集合页面。
- 全局集合导航与软件 Dock、作品切换器、资产分类导航保持独立的操作层级。
- 浏览器前进后退、刷新、直达链接与快速连续选择均需得到正确状态；动效可打断，以最后一次选择为准。

## 4. 软件：What I prefer

- 分享相对小众、好用、精致且值得学习的软件与工具，侧重偏好、欣赏和个人判断，不组织为常用软件导航或工作台清单。
- 介绍可包含截图、设计细节、使用体验与作者公开开发过程；按实际内容编排，不要求统一栏目。区分自身观察与引用，标明来源。
- Dock 贴近视口底部并保留安全间距，除标题、Dock 与必要间距外的可用高度全部交给主体；矮屏允许页面自然滚动，手机保留底部可达的横向 Dock。
- 底部 Dock 切换软件，上方一次展示当前软件。通常左侧为固定截图 / 轮播及媒体缩略图，右侧为讲述区；不同软件允许各自编排。桌面图片区宽度以整组截图在可用高度下最宽的一张为依据，并为介绍保留最低阅读宽度；其余宽度交给介绍区。截图等比完整显示，竖屏软件不沿用横屏软件的宽栏；同组切图不改变分栏宽度。
- 横屏或混合比例软件保留居中的真实画面缩略图轮播，不放说明文案或数字页码；每个缩略图及其外框按实际比例调整，点击区域至少 44 × 44px，选中描边不被滚动边界裁切。
- 整组为竖屏截图的软件使用更大的主图展台，图片上下撑满可用高度，左右小箭头切换，移除下方缩略图条。为箭头保留独立横向空间，图片保持比例、不裁切；单图不显示切换箭头，键盘可完成相同操作。窄屏设备按实际图片比例分配主图高度。
- 桌面截图区与文案预览保持固定可用高度，文案预览不内部滚动、不随文字增长撑长展台或挤走 Dock。
- 文案完整显示时不出现展开按钮；实际溢出时提供阅读全文入口。桌面使用可滚动的遮罩阅读弹窗，手机使用全屏阅读层。
- 关闭阅读层保留当前软件与媒体选择；提供清楚关闭方式、Escape、焦点管理及背景防误操作。
- 软件间切换借鉴 macOS 窗口向旧 Dock 图标收起、从新图标展开，保持图标与内容的空间对应。

## 5. 作品：What I make

- 作品数量较少，主要是软件，允许未来扩展到嵌入式与硬件；布局不依赖大量成熟作品。
- 以强交互展示、作品特点和下载等入口为重心。功能不便直接在网页体验时，设计有参与感的展示过程；长文作为可扩展补充。
- 桌面右侧悬浮区竖排作品 logo，相对左侧完整主内容区垂直居中；左侧是当前作品的大面积定制展示区，作品切换采用上下滑动过渡。
- 外层选择、导航与切换规则一致；每件作品内部按特点决定布局和交互，不固定通用图文模板。
- 作品内容通过前端静态注册表与专属 React 组件维护，不要求通过通用资源后台录入；公用的作品切换外壳保留，数据边界详见 `architecture.md`。
- 下载、体验与仓库等入口按实际情况清楚提供，不以看完动画或介绍为前提。

## 6. 工程资产：What I keep

- 重心为直观、清晰，表达长期使用并沉淀保留的资产。
- 收录方向包括机械动力、mek 等 mod 的多方块蓝图，以及 SFM 代码与相应产线的 3D 空间结构。
- SFM 执行流程追踪可视化是目标需求，不表示当前能力或确定的技术实现。

| 层级 | 已确认结构与行为 |
| --- | --- |
| 全局 | 披萨分类居中，大小保留视觉重心，上下及周围留出缩略预览空间；不在右侧放独立说明文案 |
| 预览 | hover / focus 轻微、平滑放大当前扇形，带缩略图的小气泡出现在对应方位；点击才进入分类 |
| 分类场景 | 点击后向对应方位运镜、放大，可用缩略图共享元素过渡；实际产线图、结构图或图标以回忆场景般的空间分布呈现条目，不加场景级装饰坐标轴 |
| 单项详情 | 条目的名称、缩略图共享过渡到遮罩弹窗对应位置，关闭时反向收拢；内部按资产类型单独设计 |
| 返回 | 入口采用圆或扇形的一部分，位于进入扇形的反侧；右上进入则左下返回，其他方位同理，返回时缩回全局 |

分类场景延续全局空间关系。关闭详情回到原场景，保留视角和条目位置；不通过无限缩小条目维持全景。

## 7. 转场与跨端约束

- 核心路径为挑选收藏牌、抽出、放大展开到集合，再收拢返回；标题、关键媒体和板块身份通过共享元素保持连续。
- **两条共享元素路径需要独立定义**：收藏牌到集合页左侧大标题；首页右上 `prefer / make / keep` 到集合页右上胶囊词项。不要把同一词项同时指定为两个转场终点，也不将头像纳入路径。
- 抽牌与展开是主视觉焦点，右上文字到胶囊的转场可以稍微错峰，避免两组动效互相争抢。优先验证词项的大小、位置、大小写和字宽变化；移动端若跨距过大，可降级为局部位移与显隐，不强求长距离飞行。
- 挑选时当前牌抬起、适度归正，相邻牌让位；确认后当前牌进入前景，其余牌退开；返回恢复熟悉的牌阵。
- 灵动感来自空间层次和节奏，避免依赖持续漂浮或强烈鼠标追踪晃动。
- 按钮反馈短促，按下轻微收紧；Dock 与作品切换迅速响应、运动连贯；抽牌、展开与场景运镜更舒展，有加速与落定。
- 回弹只在抽牌、抬起等空间动作中少量使用，文字与阅读层平稳落定。
- 页面动画需可打断、反向、取消；直接访问页面无需补播选牌，不支持动画时仍可正常导航。
- 手机保持同样的内容、选择关系与返回路径，根据可用空间与输入方式重新编排，不等比例缩小桌面稿。
- 手机选牌单击即可进入，减小倾斜与重叠；触屏不依赖 hover，避免多层滚动和手势争抢。
- 保持键盘操作、清晰焦点、滚动位置与返回体验；reduced motion 下保留相同信息与操作能力。

## 8. 视觉语言与排版

- 材质以光滑、精密的现代软件界面为主，收藏牌有轻微厚度与抬起反馈。
- 画布接近中性的微冷白，表面稍亮，通过细边界和轻阴影建立层次；牌面保留半透明素材背景。
- 材质按用途分工：收藏牌半透明并保证标题清楚；集合胶囊、Dock 与作品切换器采用接近实色的浅色悬浮表面；阅读层与资产详情采用稳定的实色表面；弹窗用中性灰遮罩淡化背景。
- 背景模糊仅在悬浮导航压住复杂内容时少量使用，不作为全站默认材质。透明度、模糊和遮罩的具体参数不随材质方向自动定稿。
- 清透蓝集中用于选中、链接、主要操作和焦点等交互反馈；素材保留自身颜色。
- 收藏牌适度圆角，保持修长利落；阅读层与弹窗稍柔和；按钮小圆角，胶囊形主要用于集合导航。

| 字体角色 | 中文 | 英文 |
| --- | --- | --- |
| 界面、导航、按钮与主标题 | MiSans | Manrope |
| 软件 / 作品长文 | Noto Serif SC | Source Serif 4 |

- 界面主标题稍厚实、轮廓鲜明，不要求所有文字加粗；长文采用独立阅读节奏，文中的控件仍用界面字体。
- 已接受的试排起点：长文桌面 18px、手机 17px，中文行高约 1.8；导航和按钮 14–16px。这些是排版起点，不代表全部参数定稿。
- 中文不机械套用拉丁标题负字距或紧行高；混排可按实际字面大小做有理由的光学微调。

### 图标与图形语言

- 控件使用统一的线性图标库；多数操作在图标能明确表意时优先仅显示图标，含义不明确时保留文字。
- 仅图标按钮具有明确的可访问名称、悬停与键盘聚焦提示、可见焦点，以及至少 44 × 44px 点击区域；触屏操作不依赖悬停才能理解入口。
- 软件与作品保留原生 logo；工程资产优先使用真实结构图与蓝图缩略图。装饰图形少量使用，表现力主要来自素材、构图与动效。

## 9. Token 与可用性约束

- 间距以 4px 为基础阶梯：关联内容更近，独立分组更远；内部紧凑，主要展示区域舒展，为展开动效保留空间。
- 间距、字号、行高、字重、圆角、颜色、阴影与层级均使用有限且有明确用途的 token；先记录角色与确认状态，再映射到实现。
- 基础 token 表示尺度，语义 token 表示用途，组件 token 只服务真实差异；避免逐处任意取值与无需求扩建系统。
- 阴影表达空间层级，普通内容优先用留白、表面差异与细边界分隔。
- 覆盖 hover、pressed、focus、disabled 等必要状态；普通文字对比度至少 4.5:1，大字与必要控件边界至少 3:1，不能只靠颜色表达状态。
- 触控目标以至少 44 × 44px 为基线；素材失败时仍需识别入口，加载、空内容、失败、未找到状态应有清楚层级与返回路径。
- 动效明确指定属性，不使用 `transition: all`；时间、缓动、位移和空间层级按设计目的决定，不直接接受库默认值。
- [项目 Refactoring UI skill](../.agents/skills/refactoring-ui/SKILL.md) 是质量约束；其示例配色、数值、模板与动效上限不替代本项目已确认设计。

## 10. 设计维护

- 每次确认设计点，同步更新本文与 [独立 HTML 主题稿](mockups/theme.html)，方便查看实际效果；仅在本文保留已确认内容。
- 讨论依据、试排候选、未决问题和被替代方案写入 [设计过程记录](design-process.md)，不要求常规开发读取。
- 原型不构成正式实现或其全部参数的批准；原型入口与能力说明见 [mockups/README.md](mockups/README.md)，草图保存在 `docs/design-assets/`。
