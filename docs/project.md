# Klasma 项目说明

## 1. 项目定位

Klasma 是一个以个人使用与表达为先的精选资源库和作品展示站，同时也是连接创作者个人站点的入口。公开首页会展示会枝 / huizhiLLL 的身份与相关链接，避免将它包装为面向大众的商业资源导航产品。

它收集的是创作者真正使用过、制作过、筛选过，并且认为值得留下和分享的东西：工具软件、个人作品，以及可复用的 Minecraft 等媒体资源。它不是试图覆盖所有内容的资源导航站，也不以资源数量和更新频率为目标。

名称 Klasma 来自希腊语 `κλάσμα`，有“碎片、片段”之意。项目希望把散落在不同位置、但有实际价值的数字碎片收拾起来，形成可以复用、分享和持续维护的个人档案。

## 2. 背景与动机

- 在不同 Minecraft 整合包之间复用个人偏好的 Mod、材质包、资源包和配置，减少重复下载和整理。
- 保存机械动力蓝图、SFM 代码、产线流程图等经过实践验证的 Minecraft 资产。
- 汇总自己开发的软件和小项目，提供作品介绍、下载入口和相关链接。
- 将 GitHub Releases、OpenList、自建分发地址等已有渠道统一展示，不强迫所有文件迁移到 Klasma。
- 通过 GUI 低成本录入和维护内容，避免为了增加一条资源而修改代码和重新发布。
- 在功能闭环稳定后，持续打磨具有个人巧思的 UI、交互和动效。

## 3. 内容范围

### Tools · 工具与软件

以“软件 / What I prefer”表达个人偏好与欣赏，侧重分享相对小众、很好用且值得学习的软件、网站和工具。重点讲述欣赏的具体细节、使用体验，以及有来源的设计取舍和开发故事；不以常用软件导航为组织主线。平台、版本及访问或下载链接在需要时提供。

### Projects · 个人作品

自己开发的软件和项目，兼具作品集和分发入口的作用。公开展示以强交互的呈现过程、作品特点与下载等行动入口为重心；功能不便在网页直接体验时，可通过可操作的展示过程表达。背景、技术说明和开发记录作为扩展内容，不以长篇介绍为主。现有作品主要为软件，未来允许扩展到嵌入式与硬件。

### Library · 可复用资源

以 Minecraft 资源为起点，但不把板块永久限制在 Minecraft。第一批资源包括 SFM 脚本、产线流程图、机械动力蓝图、资源包和客户端配置。后续可扩展到开发模板、自动化脚本或其他可复用资产。

一条资源可以由多个文件和链接组成。例如一条产线可以同时包含 SFM 源代码、流程图、蓝图、截图、适用整合包和教程链接。

2026-10-29 设计补充：工程资产以直观、清晰为侧重，当前收录偏好包括机械动力、mek 等 mod 的多方块蓝图，以及 SFM 代码和对应产线的 3D 空间结构。外层采用披萨式分类菜单、分类运镜与场景化条目分布，单项通过遮罩弹窗展开，具体设计见 `docs/design.md`。SFM 执行流程追踪可视化是目标需求，追踪来源、实现方案及落地阶段待定，不代表当前已支持或自动纳入首版。

## 4. 第一版功能需求

### 公开前台

- 首页在三张收藏牌上方整合头像、名称、简短签名、社交入口及 Blog / Weekly 链接；用简短词源解释和实际内容说明，让初访者理解 Klasma 的含义与用途，不采用商业 Landing Page 的营销话术。
- 首页三张收藏牌承担进入集合的导航；集合页右上角提供 Home 图标 + Prefer / Make / Keep 的胶囊切换，允许在三个集合间直接导航，左侧 `What I ...` 标题的第三词以竖向滚轮动效联动。Home 是独立图标，**不与首页头像做共享元素过渡**。
- 软件展台采用固定高度文案预览，内容溢出时通过阅读全文弹窗展示可滚动全文；移动端为全屏阅读层，不在展台内部嵌套滚动。
- 响应式按不同设备重构空间布局和操作方式，维持相同导航语义；作品与工程资产的移动端布局仍需验证。
- 展示三个内容板块，公开集合页按个人偏好组织顺序与定制布局，不强制采用统一资源列表。
- 查看资源详情，包括简介、个人说明、标签、版本或兼容性信息、外部链接和附件。
- 公开展示避免或尽可能减少搜索、筛选与高密度信息，优先通过个人编排组织内容；既有查找能力不要求在前台默认呈现控件。
- 支持草稿与已发布内容的公开状态区分。
- 对代码、流程图和图片提供适合的预览或复制体验。
- 为资源保留稳定 URL，便于分享和从博客等其他内容跳转。

### 管理后台

- 仅允许本人访问管理界面和写入接口。
- 新增、编辑、删除资源。
- 保存草稿、发布和取消发布。
- 管理标签、外部链接、图片和附件。
- 根据资源类型显示差异化字段。
- 支持录入 R2 文件和外部分发链接。
- 初期以低录入成本为原则，不要求一次填写所有字段。

### 第一版明确不做

- 不做完整的公共投稿、多人协作和评论系统。
- 不做复杂的账号体系，后台身份验证交给 Cloudflare Access。
- 不强求自动同步 GitHub Release 或 OpenList，先保留手动录入。
- 工程资产的 3D 结构展示与 SFM 流程追踪已经记录为目标需求，具体方案和阶段待定；不将其视为已实现的首版能力。复杂版本历史、依赖图和专业搜索服务仍不提前实现。
- 不为了“资源导航站”的完整度收录与个人使用无关的内容。

## 5. 成功标准

第一阶段完成后，应能从管理后台新增一条资源，保存到 Cloudflare D1，公开页面通过 API 读取并展示；资源可以附带外部链接或文件附件。之后能够完整录入一个个人作品和一条带脚本、流程图或蓝图的 Library 资源。

## 6. 产品原则

1. 先服务本人，再自然地服务访客。
2. 统一资源底座，按类型差异化展示。
3. 文件可以留在合适的分发渠道，Klasma 负责组织、说明和发现。
4. 后端保持平淡和稳定，把复杂度预算留给前台的呈现与交互。
5. 先建立可用骨架，再逐步形成完整设计语言。

## 7. 待决策项

- 除已确认的三张牌标题外，公开站点的文案语言与中英文比例。
- 是否需要可视化 Markdown 编辑器；当前已有 Markdown 内容渲染与净化。
- R2 中直接托管哪些文件，哪些只保存外部链接。
- 个人长期使用是否需要独立的快捷查找入口；不作为当前公开集合页的默认设计要求。
- Cloudflare Access 的具体登录方式和生产域名配置。
