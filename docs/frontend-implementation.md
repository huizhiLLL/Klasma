# 正式前端实施准备

2026-10-29。依据已合并的 PR #4、`design.md`、`architecture.md` 与用户认可的独立原型编排实施。本文是工程实施建议，不新增视觉定稿；实际进度仍记在 `roadmap.md`，具体设计讨论仍记在 `design-process.md`。

## 本轮执行调整

2026-10-29 用户批准按顺序实施并按颗粒度提交，包含此前准备改动。公开前台先使用完整 mock 数据评审设计，覆盖长短文案、多媒体、分类场景、附件、空状态与不同作品交互；确认效果后再接真实 API。mock 不写入 D1 / R2，后台和旧资源链接仍使用既有服务。下文的真实数据闭环在本轮先由同形状的 mock 数据边界承接，不把样例作品当作已发布的个人作品。

## 1. 已确认边界

- 进入正式 React 前台实施阶段，不再以补完所有 mockup 参数为前提。
- 软件与工程资产使用 D1 / R2 和现有后台；作品使用构建期类型化注册表与专属 React 组件。
- 首页、集合导航、字体、token 和动效语法共享；三集合内部保持不同布局。
- 保留 `/admin`、`/resource/:slug`、现有 API 和附件访问。核查历史作品数据前，不删除 schema、D1 记录或 R2 对象。
- `docs/mockups/` 保留为独立参考，不直接导入其 DOM 脚本、整份 CSS 或本地字体缓存。
- 沿用 `design.md` 的浅色、现代收藏牌、两条独立共享元素路径、Lucide、界面 / 阅读字体分工。具体数值仍为实施试值。

## 2. 当前代码与需要先解决的问题

| 当前真实实现 | 实施含义 |
| --- | --- |
| `src/App.tsx` 同时包含路由、首页、列表、详情和后台 | 先分离路由、后台与动态资源边界，避免新旧页面长期堆在入口 |
| 路由 state 只保存 pathname，集合来自 `?type=` | 路由状态必须包含 pathname 与 search；同路径不同查询、历史返回也要更新 |
| `src/App.css` 和 `src/index.css` 使用全局暗色、标题、按钮样式 | 先隔离后台与兼容详情样式，再给公开前台建立浅色 token，避免全局替换导致表单不可读 |
| 公开列表 API 返回资源行，详情 API 才返回 links / tags / assets | 软件展台先按 slug 读取详情；媒体、logo、分类排序字段需明确映射，不能假设列表已有附件 |
| 后台三类都可新增，动态作品仍存在于类型与 API | 前台作品改为单一静态来源；后台停止新增作品，但保留历史记录编辑与访问 |
| 原型字体缓存按固定样张文字准备且被 Git 忽略 | 正式字体必须覆盖后台未来录入的中文；不能复制固定字集缓存当生产字体 |
| Worker 已配置 SPA fallback，Vite 已代理 `/api` 到 8787 | 沿用同域部署和本地双服务；增加公开路由不需要新服务或新账号 |

## 3. 首批实施范围

目标：建立能够承接设计的真实应用骨架，保持现有功能可用。首批包含以下两个可独立验证的小批次；每批完成时都能正常构建和访问，不要求一次完成三个集合。

### A. 路由、内容来源与样式边界

建议提交：`refactor: 拆分前台路由与后台并建立混合内容边界`。

- `src/App.tsx` 只保留路由分发与应用级状态；保留 React、TypeScript、Vite 和原生 CSS。
- `src/app/routing.ts` 统一解析、导航与历史订阅，状态同时包含 pathname / search；内部导航只拦截同源普通左键，保留新窗口、下载与外链的原生行为。
- `src/shared/resource.ts` 放现有动态资源类型；新公开动态集合只允许 tools / library，兼容资源类型仍允许 projects。
- `src/admin/AdminPage.tsx` 与 `src/admin/admin.css` 提取现有管理功能并限定样式作用域；保留密钥、编辑、发布、附件上传 / 删除。新建类型仅为软件、工程资产；编辑历史作品时保留其原类型，不将其偷偷转为其他类型。
- `src/app/pages/LegacyResources.tsx` 与配套 CSS 保留现有动态列表及 `/resource/:slug` 详情，继续使用 marked + DOMPurify。它是过渡兼容实现，后续由 Tools / Library 展台接替集合入口。
- `src/app/features/projects/registry.ts` 建立类型化静态注册表，字段限定 slug、名称、logo、排序、外链和组件加载器；`ProjectsPage.tsx` 读取注册表，组件延迟加载。没有真实作品时显示明确空状态，不虚构已完成作品，不回读 D1 补成列表。
- 新增未知路径 / slug 的未找到状态，提供回首页或对应集合入口，避免错误路径静默显示首页。

公开路由建议：

| URL | 首批行为 | 后续稳定职责 |
| --- | --- | --- |
| `/` | 首页，第二小批替换为收藏牌布局 | 首页 |
| `/tools`、`/tools/:slug` | 现有软件列表 / 详情的兼容呈现 | 当前软件展台与选择 |
| `/projects`、`/projects/:slug` | 静态注册表作品外壳 / 对应组件；空数据或不存在时明确反馈 | 作品集合与单件定制展示 |
| `/library`、`/library/:category` | 工程资产兼容列表，分类路径保留选择 | 全局披萨分类 / 分类场景 |
| `/library/:category/:slug` | 直接读取动态资源；校验类型和分类 | 场景内可直达的详情层 |
| `/resource/:slug` | 保持旧动态详情，包含历史作品 | 兼容旧分享链接；不自动与静态作品同名匹配 |
| `/admin` | 现有管理页 | 私有管理入口 |
| `/?type=tools`、`/?type=projects`、`/?type=library` | 用 replace 导向相应新集合，不多留一条历史记录 | 旧集合链接兼容；旧动态作品仍通过原详情链接访问 |

路由中的选择是真实状态来源，不能另设不随历史变化的 activeIndex。初始加载、刷新与 popstate 直接显示当前页面，不补播选牌动画。静态作品 slug 与历史动态 slug 若相同，也不在未审核映射时自动重定向。

### B. 设计基础、首页与集合外壳

建议提交：`feat: 落地浅色收藏牌首页与集合导航`。

- `src/app/styles/tokens.css` 建立角色有限的 CSS 变量：画布 / 表面 / 悬浮层 / 牌面 / 正文 / 次级文字 / 边界 / 蓝色交互 / 焦点 / 遮罩，4px 间距阶梯，按钮 / 牌面 / 阅读层圆角，反馈 / 局部切换 / 空间转场节奏。沿用主题稿候选作为首轮实现值，在说明中保留候选状态。
- `src/app/styles/public.css` 承载浅色公开外壳、响应式和阅读排版；后台样式单独限定作用域。`src/index.css` 仅保留中性重置和默认字体，移除强制全局暗色；旧后台 / 详情颜色由自身容器承担。
- `src/app/components/CollectionShell.tsx` 共用左侧 What I 标题滚轮和右侧 Home / Prefer / Make / Keep 胶囊，正确标记当前集合；公开导航不出现管理入口。
- `src/app/pages/HomePage.tsx` 落地左侧身份与链接、右上空间说明、站名释义和三张平衡但灵动的收藏牌。无真实链接的 Blog / Weekly 显示为不可用文本，不伪造地址；媒体缺失使用清楚的标题和中性备用画面，不把虚构 logo 当真实素材。
- `src/app/animations/NavigationMotion.tsx` 协调收藏牌到左侧集合身份、三个说明词到胶囊的两条路径，使用互不重复的共享标识；不涉及头像到 Home。连续选择按最后一次导航落定，返回与直接访问不依赖动画成功。
- 正式动效沿用架构中的 Motion for React 方向；CSS 负责普通 hover / focus / pressed，不同时引入 GSAP。原型 View Transition 实现只作为行为参考，不让两套机制竞争同一对象。
- 窄屏重新编排身份、说明和竖向牌组，胶囊保持可触达；说明词可直接显隐。键盘和 reduced motion 不播放大幅空间动画，44px 目标与清楚焦点保留。
- 生产图标使用同一 Lucide 来源：首批复用已核对许可的 SVG 子集，放入 `public/icons/lucide/`，保留来源与许可；由统一 `Icon` 组件引用，不把正式应用指向 `docs/mockups/`。
- 仅准备 MiSans、Manrope、Noto Serif SC、Source Serif 4 四种生产字体，将字体资源及各自许可作为正式静态资源管理。中文使用覆盖动态录入内容的字集 / unicode 切片，拉丁与中文按字符范围分工，保留系统回退与 font-display: swap；不发布七组对照字体或固定样张切片。

数据流保持单向：

```text
URL + 历史事件 → 路由状态 → 首页 / CollectionShell / 后台 / 兼容详情
                                ├─ Tools / Library → 公开 API → 动态内容
                                └─ Projects → 静态注册表 → 专属组件
导航操作 → 路由提交 + 动效协调 → 新 URL 与对应界面
```

首批预计修改超过 8 个文件，主要是从集中入口拆出已有职责与新公开外壳；不新建服务，不调整 D1 schema，也不改变鉴权方式。每完成一个职责再同步实际目录索引，不预先创建规划中的全部空目录。

## 4. 后续集合闭环

首批通过后按以下顺序推进；它们是后续任务边界，不表示本轮已实现。

1. **软件真实数据闭环**：统一详情请求与取消过期响应；固定媒体 / 文案预览、ResizeObserver 判断溢出、桌面 dialog / 手机全屏阅读、底部 Dock 收起展开。保留 marked + DOMPurify，缺图、加载、失败和短文状态都能使用。
2. **工程资产真实数据闭环**：先明确现有 metadata 与分类、缩略图、排序的映射，再实现 hover 预览 / 点击进入、触屏两步进入、稳定场景位置和 URL 详情层。直接访问详情时重建对应场景；关闭返回原分类，返回全局位置与分类方位一致。不在该批承诺 3D 引擎或 SFM 追踪。
3. **一件真实作品闭环**：以用户选定的实际作品注册专属组件与有效下载 / 仓库入口，完成右侧 logo 切换、移动布局和上下换场。只在存在该作品的明确演示需求时增加专用交互，不先做通用作品编辑器。

## 5. 验证与交付

每批必须运行 `npm run typecheck`、`npm run lint`、`npm run build`。路由兼容、资源类型边界与异步切换需要有针对性的逻辑验证；不为样式变量逐条写镜像测试。

人工验收按以下路径执行：

- 首页到三个集合、集合互切、返回首页；快速连续选择不会让标题、胶囊与 URL 分离。
- 新旧 URL 的直接打开、刷新、前进后退；非法 type、未知 slug、缺失分类正确反馈；修饰键点击保留原生行为。
- 静态作品列表不请求动态 projects API，历史 `/resource/:slug` 仍可读取。
- 后台密钥入口、已有资源编辑和附件能力不受浅色公开样式影响；不在前台暴露管理入口。
- 软件 / 工程资产无数据、API 不可用、无媒体时都有清楚状态，不用演示假数据掩盖失败。
- 桌面与 320 / 360 / 375 / 390 / 430px 样本，长中文标题、长英文名称、字体延迟与加载失败、键盘和减少动态均能访问。

浏览器自动化和截图验证仍遵守用户主动要求后才使用的约束；静态检查通过不能替代视觉验收。部署沿用现有 GitHub Actions；本地实现、提交、推送与线上生效分别报告，推送 / 发布按用户授权执行。

## 6. 依赖、风险与回退

- 沿用现有 Cloudflare 绑定、OAuth 与 GitHub 部署凭据；首批不要求新增账号、密钥或数据库权限，不读取或输出 Secret 内容。
- 路由先沿用 History API，样式先沿用原生 CSS；不同时切换到 TanStack Router、Tailwind 或新的全栈框架。
- Motion 是首批唯一建议新增的运行时动画依赖；引入时使用 npm 更新依赖和 lockfile，并检查构建体积与减少动态行为。尚未执行安装。
- 首批最大风险是旧全局 CSS 污染、URL 兼容和动画状态竞态，先通过拆分作用域与单一路由状态降低风险。
- 真实作品、实际 logo / 截图、个人站点链接不足时，只限制对应内容的完成范围；路由、外壳和首页布局不依赖捏造内容才能落地。
- 首批只改前端代码 / 静态素材，不执行远程写数据、迁移或删除操作；可通过回退对应代码提交恢复旧前端。若将来改 API 或迁移，另行记录兼容与回退方案。
