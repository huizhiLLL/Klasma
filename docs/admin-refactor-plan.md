🥷 # 后台管理重构实施文档

> 本文面向 AI 编程执行。目标是重构 Klasma 后台的布局、信息层级和交互表现，不改变现有 API、数据模型、鉴权方式和发布规则。

## 1. 执行目标

将当前后台改造成紧凑、直观、可快速录入的内容工作台：

- 列表页首屏能看清集合、筛选、内容状态和主要操作。
- 编辑页首屏能完成名称、简介、正文入口、保存和发布。
- 软件与工程资产共享编辑器骨架，差异字段保持清楚。
- 使用图标、位置、数量、状态和颜色表达信息，减少重复说明。
- 桌面端使用双栏工作台，移动端使用单列和固定保存操作。
- 继续遵守现有后台 API、数据字段、发布校验和未保存保护。

不实现以下内容：

- 不新增统计首页。
- 不增加多人协作、版本历史或权限体系。
- 不修改 D1 schema、迁移文件、API 路由和资源类型。
- 不把历史作品改造成通用编辑器。
- 不接入 `docs/mockups/` 的脚本或样式。
- 不使用设计截图中的示例数据替换真实 API 数据。

`src/admin/components/`

如果实现中发现现有组件无法满足布局，可调整组件接口，但保持数据流和 API 调用行为不变。

## 3. 页面结构

后台包含三种状态：

1. 未登录页
2. 内容列表页
3. 内容编辑页

整体结构：

```
.admin-app
└── .admin-shell
    ├── .admin-header
    ├── .admin-list-page
    │   ├── .admin-collection-switcher
    │   ├── .admin-list-toolbar
    │   ├── .admin-list-summary
    │   └── .admin-list
    └── .admin-editor-page
        ├── .admin-editor-bar
        └── .admin-editor-grid
            ├── .admin-editor-content
            └── .admin-editor-settings
```

页面不再依赖多个大面积卡片。主要分组使用底线、浅色背景或紧凑边框表达。

## 4. 全局布局与 token

在 `src/admin/admin.css` 中建立后台专用 token，优先使用 token，不在组件中随意写新数值。

建议起始值：

```css
.admin-app {
  --admin-content-width: 1440px;
  --admin-sidebar-width: 280px;
  --admin-toolbar-height: 56px;
  --admin-control-height: 36px;
  --admin-touch-height: 44px;

  --admin-space-1: 4px;
  --admin-space-2: 8px;
  --admin-space-3: 12px;
  --admin-space-4: 16px;
  --admin-space-5: 20px;
  --admin-space-6: 24px;

  --admin-control-radius: 8px;
  --admin-panel-radius: 10px;
}
```

约束：

- 间距只使用 4px 阶梯。
- 桌面端页面左右边距为 24 至 32px。
- 控件高度为 36 至 40px，触屏端至少 44px。
- 后台正文使用 14 至 16px。
- 分组标题使用 15 至 18px。
- 页面标题不超过 24px。
- 普通文字对比度至少 4.5:1。
- 所有交互元素保留可见焦点。
- 不使用 `transition: all`。
- reduced motion 下保留内容和操作能力。

## 5. 顶部全局栏

组件：`AdminPage.tsx` 中的 `.admin-header`

结构：

```
左侧：Klasma / 内容管理
右侧：前台、退出
```

要求：

- 高度约 56px。
- 左侧品牌保持现有文字。
- “查看前台”可以使用外链图标加短文案。
- “退出”保留文字，避免误触。
- 不在顶部放重复的页面标题。
- 登录状态未确认时，顶部仍可正常渲染，不显示错误状态。

## 6. 列表页重构

### 6.1 集合切换

组件：`AdminPage.tsx` 中的 `.admin-tabs` 或新建 `CollectionSwitcher`

将当前大面积标签改为紧凑 segmented control：

```
[▣ 软件 1] [◈ 工程资产 0]
```

要求：

- 高度约 36px。
- 选中项使用浅蓝背景或清晰底线。
- 数量使用次级颜色。
- 不再额外显示重复的集合大标题。
- 历史作品只有存在数据时显示。
- 切换集合时保留现有筛选重置逻辑。

### 6.2 页面工具栏

组件：`AdminPage.tsx` 中的 `.admin-filters`

结构：

```
[搜索名称、Slug、标签] [状态] [分类] [排序] [新建]
```

要求：

- 搜索框占据剩余宽度。
- 状态、分类、排序使用短标签。
- 工程资产才显示分类筛选。
- 新建按钮靠近集合切换和工具栏右侧。
- 不新增额外筛选条件。
- 保留现有 query、status、category、sort 状态和过滤逻辑。

建议文案：

- `搜索名称、Slug、标签`
- `状态`
- `分类`
- `排序`

### 6.3 列表行

组件：`ResourceList.tsx`

每一行结构：

```
[缩略图]  标题
          简短说明或分类
                              状态  日期  >
```

要求：

- 行高约 64 至 72px。
- 缩略图固定 40px。
- 标题是最高层级信息。
- 简介最多显示一行，超出省略。
- 状态使用图标、颜色和短标签。
- 日期右对齐。
- 整行可进入编辑页。
- 保留键盘操作和 aria-label。
- 不显示重复的 slug，除非没有简介。
- 工程资产显示分类，软件显示简介。

推荐状态：

- 草稿：空心圆 + “草稿”
- 已发布：实心圆 + “已发布”

### 6.4 空状态

组件：`AdminPage.tsx` 或新建 `AdminEmptyState`

无内容时：

```
[文件夹图标]
暂无软件
[+ 新建]
```

有筛选条件但无结果时：

```
没有匹配内容
[清除筛选]
```

要求：

- 不显示大段解释。
- 主要操作必须保留。
- 不使用示例内容填充空列表。

## 7. 编辑页重构

### 7.1 编辑顶部栏

组件：`EditorBar.tsx`

结构：

```
[返回] 资源名称 / 类型       状态       保存    发布
```

要求：

- 高度约 52 至 56px。
- 桌面端吸附在顶部。
- 移动端固定在底部。
- 返回、保存、发布保持现有行为。
- 发布按钮只在允许发布时显示或保持禁用状态，遵循现有逻辑。
- 状态使用短文本：
  - 新建
  - 未保存
  - 已保存
  - 保存中
- 不显示重复说明句。

### 7.2 首屏基础信息

组件：`AdminPage.tsx` 中的编辑表单区域

结构：

```
名称
[输入框]

一句话说明
[单行或两行输入框]
```

要求：

- 名称输入框高度约 44px。
- 名称字号约 20 至 24px。
- 简短说明最多显示两行。
- 不使用过高的空 textarea。
- placeholder 直接表达用途。
- 新建时名称仍然可以单独保存草稿。
- slug 为空时继续使用现有自动生成逻辑。

### 7.3 内容分组

组件：`Disclosure.tsx`

分组顺序：

1. 正文
2. 媒体
3. 链接
4. 类型专属字段

显示形式：

```
▾ 正文                       编辑 · 预览
▸ 媒体                       2 项
▸ 链接                       3 项
▸ 软件信息
```

要求：

- 分组标题高度约 44px。
- 分组内容默认状态沿用现有行为，避免改变用户已有习惯。
- 展开区减少外层圆角和大面积留白。
- 媒体、链接显示当前数量。
- 空内容只显示一个添加入口。
- 正文编辑与预览保持原位切换，不改为弹窗。
- 继续支持 Markdown、代码、链接、上传、删除和保存设置。

### 7.4 正文区域

要求：

- 编辑区高度约 360 至 420px。
- 编辑 / 预览切换使用紧凑 segmented control。
- 编辑状态使用等宽字体或当前代码样式。
- 预览状态继续使用现有 Markdown 渲染组件。
- 不显示重复的“Markdown 正文”大标题。
- 保留正文未保存保护。

### 7.5 设置栏

组件：`ResourceEditor` 中的 settings 区域

桌面端：

- 宽度约 260 至 280px。
- 吸附在编辑顶部栏下方。
- 独立滚动，不能撑开主编辑区。
- 顺序固定为：

```
发布状态
Slug
类型 / 分类
兼容信息
排序
标签
内容检查
```

设置项使用紧凑的标签和值：

```
发布状态                  草稿
Slug                      mole
排序                      0
标签                      3 个
```

要求：

- 不重复显示已经在顶栏出现的状态。
- 类型专属字段只在对应集合显示。
- 软件和工程资产继续使用现有 metadata 字段。
- 标签仍然支持输入后按 Enter。
- 不新增字段，不改变提交结构。

### 7.6 内容检查

组件：`ReadinessCheck.tsx`

改为紧凑检查列表：

```
内容检查              3 项待补充

! 简短说明
! 软件图标
! 访问或下载链接
```

要求：

- 只保留一次数量提示。
- 每条问题前使用图标。
- 问题文字保持简短。
- 可选提示使用次级颜色，不能与阻塞问题混在一起。
- 完整状态只显示：

```
✓ 可以发布
```

- 检查条件继续使用现有 `publicationErrors` 和资源类型规则。
- 点击问题时可以定位到对应字段；如果当前实现不便定位，先保留静态提示，不改变校验逻辑。

## 8. 媒体和链接区域

### 媒体

组件：`AssetList.tsx`

要求：

- 预览图约 64 至 72px。
- 文件名、类型、大小放在同一信息组。
- 说明和排序输入保持可编辑。
- “保存设置”只在有修改时显示为可用。
- 删除只显示图标，但必须有 aria-label 和 tooltip。
- 上传失败继续支持重试。
- 不改变 25MB 限制、文件类型和上传 API。

### 链接

建议每行结构：

```
[类型] [名称] [地址] [删除]
```

要求：

- 删除按钮仅显示图标。
- 网址输入占主要宽度。
- 类型和名称使用紧凑字段。
- 保留现有官网、仓库、下载、文章和其他类型。
- 新增链接按钮使用加号图标和短文案。

## 9. 移动端规则

断点以内容是否发生拥挤为准，初始可沿用现有 760px。

要求：

- 编辑器从双栏变为单列。
- 设置栏改为普通折叠区。
- 保存栏固定在底部。
- 页面底部预留安全空间，避免内容被操作栏遮挡。
- 列表行分为两行：
  - 第一行：缩略图、标题、箭头
  - 第二行：状态、日期、分类
- 搜索框单独占一行。
- 筛选器平分剩余宽度。
- 触控目标至少 44 × 44px。
- 不依赖 hover 才能理解图标含义。

## 10. 图标和文案规范

统一使用现有 `Icon` 组件和线性图标。

优先图标：

- 软件：`box`
- 工程资产：`layers`
- 正文：`file-text`
- 媒体：`image`
- 链接：`link`
- 标签：`tag`
- 设置：`sliders-horizontal`
- 检查：`circle-alert`
- 保存：`save`
- 发布：`send`
- 返回：`arrow-left`
- 删除：`trash-2`

文案压缩：

- 新建软件、新建工程资产 → 新建
- 保存草稿 → 保存
- 内容检查 → 检查
- 媒体与附件 → 媒体
- 链接与下载 → 链接
- 类型与兼容 → 类型
- 查看前台 → 前台

仅图标按钮必须：

- 有 aria-label。
- 有可见 focus 状态。
- 有 hover 或 tooltip 提示。
- 点击区至少 44 × 44px。

## 11. 执行顺序

按以下顺序实施，不要一次性重写所有逻辑：

### 阶段 1：样式基础

- 在 `admin.css` 建立后台 token。
- 调整页面宽度、顶部栏、控件高度和间距。
- 删除不必要的大圆角和大面积留白。
- 保持现有颜色语义和字体。

### 阶段 2：列表页

- 重构集合切换。
- 重构筛选工具栏。
- 重构 `ResourceList` 行布局。
- 重构空状态。
- 保持现有过滤、排序和进入编辑逻辑。

### 阶段 3：编辑顶部和基础信息

- 重构 `EditorBar`。
- 压缩名称、简介区域。
- 增加桌面吸附和移动端底部操作栏。
- 保持保存、发布、返回和未保存保护。

### 阶段 4：内容分组

- 调整 `Disclosure` 样式。
- 调整正文编辑 / 预览区域。
- 调整媒体和链接分组。
- 保持上传、删除、重试和独立保存行为。

### 阶段 5：设置栏和检查

- 调整设置栏宽度、吸附和滚动。
- 压缩字段展示。
- 重构 `ReadinessCheck`。
- 检查软件和工程资产专属字段。

### 阶段 6：响应式和可访问性

- 完成移动端单列布局。
- 完成底部保存栏。
- 检查键盘顺序、focus、aria-label、Escape 和 reduced motion。

## 12. 禁止事项

执行过程中不要：

- 修改 API 请求路径或请求体结构。
- 修改资源状态、发布规则或鉴权逻辑。
- 删除已有字段。
- 把所有内容强行塞进一个页面而取消滚动。
- 用纯图标替代没有明确含义的文字。
- 用颜色单独表达状态。
- 使用渐变背景、玻璃拟态、大阴影或装饰性图形。
- 引入新的 UI 框架。
- 复制前台页面的布局和动效。
- 用 mock 数据、截图中的内容或固定文本替代真实数据。

## 13. 验收标准

### 列表页

- 桌面 1280×800 下，顶部栏、集合切换、搜索筛选和至少一条列表内容同时可见。
- 单条内容时页面不出现异常的超大空白卡片。
- 搜索、状态筛选、分类筛选和排序行为不变。
- 整行可点击进入编辑。
- 空列表和无结果状态清楚可操作。

### 编辑页

- 首屏可见名称、简介、正文入口、设置栏和保存 / 发布操作。
- 顶部状态不与右侧状态重复堆叠。
- 正文、媒体、链接可以折叠。
- 软件和工程资产显示正确的专属字段。
- 内容检查问题短、清楚，并能说明发布阻塞原因。
- 上传、删除、重试、保存设置和发布行为不变。

### 响应式

- 760px 以下变为单列。
- 移动端保存和发布始终可达。
- 内容不会被固定底栏遮挡。
- 所有操作目标至少 44 × 44px。

### 工程验证

完成后运行：

```bash
npm run typecheck
npm run lint
npm test
npm run verify:frontend
npm run build
npm run verify:api
```

如果只完成视觉层改造，也至少运行：

```bash
npm run typecheck
npm run lint
npm test
npm run build
```

除非用户另行要求，不需要浏览器自动化或截图验证。若主动进行视觉验证，临时产物放在已忽略目录，并在完成后清理。
