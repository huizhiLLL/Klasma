# Klasma 开发路线

## 当前进度（2026-10-29）

- 阶段 0 已完成：React + Vite、Cloudflare Worker、D1、R2、Wrangler 配置和远程资源已建立。
- 阶段 1 已完成基础闭环：公开查询 API、管理 API、本地 D1 migration、最小资源录入页面和生产部署。
- 线上地址：`https://klasma.huizhi.ink`。
- 管理页通过 `/admin` 直接进入，公开前台已隐藏管理入口；当前支持 `ADMIN_KEY` 密钥校验。Cloudflare Access 的配置与完整身份验证仍待落实，不能视为已完成。
- 阶段 2 已具备基础能力：资源编辑、删除、发布状态、标签、外部链接、附件模型、R2 上传与附件删除、公开列表和详情、关键词查询、Markdown 渲染与净化。
- 阶段 2 尚待补充：类型专属字段与表单、真实资源录入验证、鉴权完善和更完整的使用验证；已有 API 不代表公开前台需要默认展示搜索筛选。
- 阶段 3 已从布局草图推进到视觉语言评审：首选字体组合已选定（界面 MiSans / Manrope，长文 Noto Serif SC / Source Serif 4），独立字体对照页与持续主题稿已建立；材质分工、强调色方向、圆角性格、4px 间距基准、动效节奏方向和 Lucide 图标规范已有明确约束。
- 仍未定稿的是主题稿中的具体色值、阴影、圆角、字号层级与动画参数；这些数值仍是候选。正式应用仍为功能骨架，未应用新设计。
- 当前新增的重点是：首页右上 `What I prefer · make · keep` 说明词到集合胶囊的共享元素转场。设计约束已记录，主题稿已加入独立样张；完整首页构图、手机布局和两条共享元素路径仍需验证。
- 接下来先评审主题稿与首页转场样张，再将同一视觉语言落实到桌面 / 手机布局原型，使用真实或代表性素材验证后，才进入正式页面实现。作品和工程资产的详情内部继续按内容定制。

## 阶段 0：项目骨架

目标：建立可运行的 React + Vite + Cloudflare Worker 项目，完成本地开发和部署配置。

验收：前端可以启动，Worker 可以响应健康检查，D1、R2 绑定方式和环境变量边界明确。

## 阶段 1：数据闭环

目标：完成资源的最小 CRUD、公开读取和后台鉴权。

范围：

- Drizzle schema 与第一版 D1 migration。
- `resources`、标签、链接、附件的基础模型。
- Hono 公共查询 API 和管理 API。
- 后台新增、编辑、草稿、发布、删除。
- Cloudflare Access 保护 `/admin` 和 `/api/admin/*`。
- 公开页面显示三类资源的基础列表和详情。

验收：从后台新增一条资源，D1 保存成功，公开页面能通过 API 展示。

## 阶段 2：三类内容完整可用

目标：让 Tools、Projects、Library 都能承载真实内容。

范围：

- 类型专属字段和表单。
- 标签、搜索、排序和基础筛选。
- Markdown 或富文本内容方案。
- R2 图片和文件上传。
- GitHub、OpenList、博客等外部链接。
- 代码预览、复制和下载。
- 录入第一批 Minecraft 蓝图、SFM 脚本、流程图和配置资源。

验收：能够完整录入一件个人作品，以及一条同时包含脚本、流程图或蓝图的 Library 资源。

## 阶段 3：设计语言与交互打磨

2026-10-28 顺序调整：暂停继续实现公开浏览页面，先详细讨论并记录 UI/UX 约束。已确认浅色单主题与现代收藏牌式首页交互，详见 `docs/design.md`；本轮只更新文档，设计确认后再围绕约束补全功能。

目标：在稳定功能之上形成 Klasma 的视觉和交互特征。

范围：

- 在已选字体组合上继续评审字号层级、行高、色值、阴影、圆角和间距 token；当前具体数值仍是候选。
- 首页个人身份、站名释义与三张收藏牌的最终构图；右上说明区采用「个人数字碎片库 / What I prefer · make · keep」。
- 验证首页右上三个词到集合胶囊的共享元素转场，并与收藏牌到左侧大标题的转场错峰协调。**不实现首页头像到 Home 图标的共享元素动画**。
- 软件区固定预览与阅读全文层的桌面 / 移动端体验；处理溢出、关闭和焦点恢复。
- 首页三个入口的构图与真实素材密度；完成首页、软件、作品、工程资产的手机竖屏结构验证。
- 集合间胶囊滑块、左侧 `What I` 第三词滚轮、内容转场、浏览器历史、连续切换与返回首页保持同步。
- 软件区底部 Dock 与固定媒体、固定预览 + 全文阅读层，作品区右侧切换与纵向换场，工程资产分类预览、场景和遮罩详情的空间关系。
- Motion 布局动画、卡片展开和共享元素转场。
- reduced motion、键盘操作和移动端体验；为首页、软件、作品和工程资产分别制作手机竖屏结构验证，未定稿的响应式布局不提前承诺。

验收：首页、分类页和详情页之间具有连续的视觉身份，且不影响读取、导航和返回。

布局与交互原型位于 `docs/mockups/`，入口和运行方式见其 `README.md`。`index.html` / `mobile.html` 验证五个主视图及展开状态；`typography.html` 与 `theme.html` 分别评审字体和持续视觉语言。主题稿新增首页说明词到胶囊的独立共享元素样张，但它不替代完整首页布局原型；手机布局仍为评审候选。原型仅供评审，不参与正式构建；浏览器验证输出保留在本地忽略目录，不作为源码提交。披萨菜单桌面采用“悬停缩略图气泡、点击后运镜进入”，触屏候选采用“点分类预览、再点缩略图进入”。

## 阶段 4：按实际需求扩展

候选方向：

- SFM 流程图交互预览。
- Minecraft NBT 结构预览或依赖可视化。
- 资源版本历史。
- GitHub Release 自动同步。
- 大文件使用预签名 URL 直传 R2。
- 更完整的全文搜索和筛选。
- 与博客、周刊或其他个人站点互相引用。

这些功能只有在真实使用中产生明确痛点后再进入开发，暂不作为首版架构前置条件。

## 每阶段的工作原则

1. 每次只推进一个可验证的闭环。
2. 先用真实资源验证模型，再抽象通用能力。
3. 发现 UI 问题时优先记录设计决策和复现条件，再调整组件。
4. 保持 API、数据模型和前台视觉解耦，方便后续重做界面。
