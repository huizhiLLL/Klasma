# 后台管理与真实内容接入

## 页面与录入

访问 `/admin/`，输入现有 ADMIN_KEY。成功后当前浏览器通过 HttpOnly Cookie 保持登录，固定 30 天过期，不滑动续期；退出删除当前浏览器会话 Cookie。密钥不写入 localStorage，旧版本存储的密钥会在进入后台时移除。前台不会显示登录框。轮换 ADMIN_KEY 可使全部旧会话失效。

后台提供软件、工程资产列表，支持名称 / Slug / 标签搜索、状态筛选、最近更新 / 名称排序，资产额外提供分类筛选。已有历史作品记录可维护，新作品在代码中注册。

新建时先填名称即可保存草稿，Slug 留空时自动生成。已创建资源不能改集合。软件与资产共用编辑骨架，主区承载说明、媒体、正文和链接；设置栏承载发布、类型字段、排序和标签；窄屏单列并保留底部保存操作。

- 软件：图标、平台、版本、截图、自由编排的 Markdown、访问和下载入口。
- 工程资产：现有分类、代码 / 产线 / 多方块类型、占地、兼容说明、代码语言、代码与注意事项、结构图和附件。
- 标签输入后按 Enter，可复用已录入标签。
- 链接逐条填写用途、名称与地址，支持官网、仓库、下载、文章和其他入口。
- 展示顺序数字较小的在前；资产分类场景位置由前台计算，不填写坐标。

素材支持本地上传和外部 URL。文件不超过 25 MB；图标、封面、截图仅支持 PNG / JPEG / WebP / GIF / AVIF，本地图片自动读取尺寸；外部图片填写真实宽高。素材说明与排序可通过素材行的“保存设置”独立保存，页面主保存也会一并提交尚未保存的素材设置；上传和删除立即生效。新资源第一次上传前自动保存草稿。失败文件可通过“重试上传”重试。

## 发布与数据边界

软件发布需简短说明、图标、至少一个访问 / 下载链接；工程资产发布需分类、简短说明，并至少提供正文、代码、素材或链接之一。截图与兼容信息可后补。已发布条目保存后立即更新线上内容；不提供独立的待发布修改版本。

公开前台仅读取已发布软件和工程资产，空数据不回退到样例。Markdown、真实截图、全部附件与链接分别映射到现有展示区。作品维持静态注册表，目前未登记真实作品，因此显示空状态；设计样例不对外展示。

删除资源时一并删除 R2 上传文件，外部源文件不删除。删除素材后若不满足发布条件，需先取消发布。草稿上传文件只向有效管理会话返回；取消发布后停止公开读取文件。外部文件源地址的权限由来源站点决定。

离开有未保存正文的编辑器时提供提示，覆盖页面刷新、关闭和站内浏览器后退。会话过期保留当前内存中的录入内容，重新登录后继续；这不是跨刷新草稿恢复，仍应及时保存草稿。

## 接口

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/admin/session` | 查询当前会话 |
| `POST /api/admin/session` | `{ key }` 登录并签发 30 天 Cookie |
| `DELETE /api/admin/session` | 删除当前浏览器 Cookie |
| `GET /api/admin/resources` | 全部资源与关联数据 |
| `POST /api/admin/resources` | 创建草稿 / 资源 |
| `PUT /api/admin/resources/:id` | 保存完整字段及发布状态 |
| `DELETE /api/admin/resources/:id` | 删除资源和上传文件 |
| `POST /api/admin/assets` | FormData 上传资源素材 |
| `POST /api/admin/assets/external` | 登记外部媒体或附件 |
| `PUT /api/admin/assets/:id` | 保存素材说明、顺序 |
| `DELETE /api/admin/assets/:id` | 删除素材 |
| `GET /api/resources?type=tools\|library` | 已发布资源及关联数据 |
| `GET /api/resources/:slug` | 已发布单条资源 |
| `GET /api/assets/:id` | 依所属资源状态检查访问后读取文件 |

所有管理内容 API 要求会话，不接受旧密钥请求头或未经验证的 Access 身份头。写入要求同源，JSON 接口使用 application/json；上传使用 multipart/form-data。元数据返回对象而非 JSON 字符串，附件提供统一 url。Slug 重复返回 409，字段错误返回 400，未登录返回 401，未知 API 返回 JSON 404。

现有 D1 schema 无变化，不添加迁移、不清理远程数据。类型字段放在 resources.metadata，媒体说明 / 宽高 / 排序放在 resource_assets.metadata；资源、链接和标签以 D1 batch 写入。

## 开发与验收

本地 `.dev.vars` 配置 ADMIN_KEY，运行 README 中的构建、本地 migration、Worker 与 Vite。生产密钥使用 Wrangler Secret，不写入配置文件。

验证命令：`npm run typecheck`、`npm run lint`、`npm test`、`npm run verify:frontend`、`npm run build`、`npm run verify:api`。API 验证启动隔离的本地 Worker / D1 / R2，使用测试密钥和临时存储，结束后清理，不操作远程数据。

手工验收：录入一款带图标 / 截图 / 长文 / 官网的软件，以及一条带分类 / 代码 / 图片 / 附件的工程资产；检查草稿隔离、排序、发布、前台直达、下载和取消发布。浏览器视觉、焦点和触屏体验另行验收。
